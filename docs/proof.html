            근거는 해시로 고정합니다

              같은 코드끼리의 대조는 검증이 아닙니다

              확률과 판정이 같은 추출기를 쓰면 추출기가 틀려도 양쪽이 똑같이 틀립니다. 그래서 추출기 코드를 보지 않고, 리플레이 경기 개 하프이닝의 GUMBO 원문을 야구 규칙으로 직접 판정해 대조했습니다.

                구속(95마일 이상)과 투수 누적 투구 수 2종은 GUMBO의 단일 필드를 그대로 읽어 독립 근거를 만들 수 없어, 아직 원문 대조를 하지 않았습니다.

                Market Deadline

                결과를 모르는 동안에만
                참여를 받습니다

                마감은 60초 타이머와 첫 투구 감지 중 먼저 오는 쪽입니다. 타이머만 있으면 쉬는 시간이 짧은 이닝에서 이미 시작된 공격에 참여를 받게 되고, 감지만 있으면 피드가 끊겼을 때 마켓이 영영 열려 있게 됩니다.

                1. 0s 공수 교대 감지 앞 마켓을 판정 · 정산하고 새 질문을 엽니다
                2. 0~60s 투표 창 남은 시간은 서버의 마감 시각 기준으로 셉니다
                3. 60s · 첫 투구 마감 · 봉인 참여 내역을 해시로 고정합니다
                4. 하프이닝 경기 진행 결과가 정해지는 구간
                5. 다음 교대 판정 · 정산 잔액에 바로 반영합니다

                피드가 멈춰도 시계는 돕니다

                • 전용 스레드가 1초마다 마감 시각이 지난 마켓을 찾아 닫습니다. MLB 호출이 늦거나 실패해도 마감은 따로 진행됩니다.
                • 경기별 잠금을 공유합니다. 피드 처리와 시간 마감은 같은 PostgreSQL advisory lock을 쓰고, 잠겨 있으면 기다리지 않고 다음 주기에 다시 봅니다.
                • 참여 API와 같은 행 잠금으로 마켓을 읽습니다. 마감 시각과 현재 시각이 같으면 참여할 수 없습니다.
                • 60초로 정한 근거 — 실측 쉬는 시간 56회 중 120초를 넘은 경우는 0건이었습니다. 60초면 46회(82%)에서 타이머가 먼저 끝나 카운트다운이 정상 완주합니다.

                봉인 해시

                SHA-256( 마켓 ID | 참여자:방향:포인트 | … | 마감 시각 )

                참여 ID 오름차순으로 순서를 고정해, 같은 입력이면 언제 어디서 계산해도 같은 값이 나옵니다. 마감 뒤에 참여를 끼워 넣었는지 확인하는 근거입니다. 참여자가 0명이어도 마감하고, 무효 여부는 정산이 판단합니다.
